# SPEC_REPORTS.md — Reports Module

**Platform:** Mission Control  
**Module:** Reports — Scheduled Web Scrapers & Report Generation  
**Stack:** Next.js 15, TypeScript (strict), Tailwind CSS, tRPC, Prisma, Zustand, TanStack Query, Framer Motion, Monaco Editor, Vercel AI SDK, BullMQ, Playwright, Recharts, Resend  
**Last updated:** 2026-05-22

---

## 1. Overview

The Reports module enables users to configure automated web scrapers that run on a schedule and produce structured, AI-enriched reports. Think of it as a personal data pipeline: define what to watch (specific product prices, job postings, news feeds, competitor sites, portfolio values), when to check, and how to be notified.

Each scraper runs server-side using Playwright in a sandboxed environment, extracts structured data, passes it through an AI summarization layer, and delivers formatted reports to the UI and optionally via email or push notification.

Five built-in templates cover the most common use cases. A sixth "Custom" template exposes a Monaco editor where users can write their own Playwright scraping scripts using a provided helper API.

Key capabilities:
- **Scheduling**: Cron-based scheduling with a human-friendly builder. Runs managed by BullMQ.
- **5 built-in templates**: Price Tracker, Job Monitor, News Aggregator, Competitor Monitor, Portfolio Tracker.
- **Custom scrapers**: Write Playwright scripts in a Monaco editor with a provided helper API.
- **AI summaries**: Every report gets a natural language summary generated by the configured Reports AI model.
- **Notifications**: Email (Resend) and/or push notifications on new reports or threshold alerts.
- **Export**: Reports exportable as PDF, CSV, or JSON.
- **Report viewer**: Template-specific rich UI (charts, tables, diff view, card grids).
- **Safety**: Scrapers run in an isolated sandbox with no access to the host filesystem or internal network.

## 2. User Stories

### US-01: Track a Product Price
> As a bargain hunter, I want to track the price of a specific product on multiple retailer URLs so that I'm notified automatically when the price drops below a target.

**Acceptance criteria:**
- User creates a Price Tracker scraper, provides product name and up to 5 URLs.
- Scraper runs on the configured schedule (e.g., every 6 hours).
- A `PricePoint` record is written per URL per run.
- The report viewer shows a line chart of price history for each URL.
- A threshold alert can be set: "Notify if price < $250." When met, a push notification is sent immediately.

### US-02: Monitor New Job Postings
> As a job seeker, I want to monitor job boards for postings matching my skills and get a daily digest of new listings so that I don't have to manually check multiple sites.

**Acceptance criteria:**
- User creates a Job Monitor scraper with keywords and optionally their job profile (pulled from the Jobs module).
- Scraper identifies new listings since last run (de-duplicated by URL).
- Report table marks each job as "new" or "seen."
- AI-generated summary estimates fit score if job profile is linked.
- Daily email delivers a formatted HTML table of new postings with apply links.

### US-03: Aggregate News by Topic
> As a researcher, I want to aggregate headlines from multiple RSS feeds and have them categorized by topic so that I can scan the day's news in one place.

**Acceptance criteria:**
- User provides RSS feed URLs and optionally preferred categories (e.g., "AI," "Finance," "Politics").
- AI categorizes each article and extracts a one-sentence summary.
- Card grid in the report viewer shows articles grouped by category.
- Read/unread state is tracked per article.
- Articles older than 7 days are archived.

### US-04: Monitor a Competitor's Website
> As a product manager, I want to be alerted whenever the content of a competitor's pricing or features page changes so that I can respond quickly.

**Acceptance criteria:**
- User provides a URL and optional CSS selector to scope the monitored region.
- Each run fetches and stores the text/DOM of the target region.
- The report viewer shows a semantic diff between the current and previous run.
- Only changes above a configurable similarity threshold trigger a notification.
- Screenshots of the page are stored on change for visual reference.

### US-05: Write a Custom Scraper
> As a developer, I want to write a custom Playwright script to scrape a site that has no built-in template so that I can extract exactly the data I need.

**Acceptance criteria:**
- The Monaco editor appears when "Custom" template is selected.
- The editor provides TypeScript autocompletion for the `ScraperContext` helper API.
- "Test Run" executes the script against a live URL and shows the extracted output in a preview panel within 30 seconds.
- Validation rejects scripts that attempt to access the local filesystem or internal network ranges.
- Once saved, the custom scraper runs on the configured schedule like any built-in template.

### US-06: Receive a Weekly Email Report
> As a user who prefers email over the web app, I want my portfolio tracker to send me a formatted HTML email every Monday morning with price movements and total portfolio value.

**Acceptance criteria:**
- User configures "Every Monday at 8am" schedule and enables email notification.
- Email is delivered via Resend with an HTML template showing current prices, day/week change, and an AI-generated market commentary paragraph.
- Email includes a "View full report" link that deep-links to the report in the web app.
- If the scraper fails, the email is not sent and the user receives a "Scraper failed" notification instead.

### US-07: View Historical Run Statistics
> As a user, I want to see the success rate and average duration of each scraper over time so that I can identify scrapers that are unreliable and fix or remove them.

**Acceptance criteria:**
- The scraper stats panel shows: total runs, success rate (%), average duration (ms), last success, last failure.
- A mini success/fail timeline shows the last 30 runs as colored dots (green/red).
- Clicking a run in the timeline shows that run's full result (or error message + screenshot if failed).
- Scrapers with a success rate below 70% are flagged with a warning badge in the left panel.

- Each card shows: name, template type, schedule text, status badge (active/paused/error), next run countdown.
- Status dots: green = active, grey = paused, red = last run failed.

- AI summary card pinned at the top of every report.

- Fields vary by template.
- Schedule picker: dropdown of common schedules + "Custom cron..." option that shows the cron input.
- Notification settings: email/push toggles.
- Output format selector.
- Threshold alert input (shown for Price Tracker, Portfolio Tracker templates).
- Action buttons: Run Now, Pause/Resume, Delete.

## 4. Built-in Report Templates

### 4.1 Price Tracker

Monitors prices of a named product across multiple retailer URLs.

```typescript
// src/server/reports/templates/priceTracker.ts

export interface PriceTrackerConfig {
  itemName: string;
  urls: Array<{
    url: string;
    storeName?: string;          // Auto-detected if omitted
    priceSelector?: string;      // CSS selector (auto if omitted)
    currencyCode?: string;       // Default: 'USD'
  }>;
  alertBelowPrice?: number;      // Notify if any price drops below this
}

export interface PriceTrackerResult {
  prices: Array<{
    storeName: string;
    url: string;
    price: number;
    currency: string;
    available: boolean;
    change7d?: number;           // % change vs 7 days ago
    change30d?: number;          // % change vs 30 days ago
```

Report viewer elements:
- **Line chart** (Recharts `LineChart`): one line per store, x-axis is date, y-axis is price. 30-day window by default.
- **Summary table**: current price per store with Δ7d and Δ30d percentage columns, colored green (drop) or red (increase).
- **Price drop badges**: prominently displayed cards for any prices that dropped since the last run.
- **Min/Max/Avg callouts**: stat cards at the top of the chart.

## 6. Scheduling

### 6.1 BullMQ Job Queue

Scrapers are scheduled and executed using BullMQ with Redis as the backing store.

```typescript
// src/server/reports/queue.ts
import { Queue, Worker, QueueScheduler } from 'bullmq';
import IORedis from 'ioredis';

const connection = new IORedis(process.env.REDIS_URL!, { maxRetriesPerRequest: null });

export const scraperQueue = new Queue<ScraperJobData>('scrapers', {
  connection,
  defaultJobOptions: {
    attempts: 3,
    backoff: { type: 'exponential', delay: 60_000 }, // 1min, 2min, 4min
    removeOnComplete: 100,
    removeOnFail: 500,
  },
});

export interface ScraperJobData {
  scraperId: string;
  userId: string;
  template: TemplateType;
  config: unknown;
  isManual: boolean;  // True when triggered by "Run Now"
}

// Worker runs in a separate Node.js process (worker.ts)
export const scraperWorker = new Worker<ScraperJobData>(
  'scrapers',
  async (job) => {
    return executeScraperJob(job.data, job.attemptsMade + 1);
  },
  {
    connection,
    concurrency: 3, // Maximum 3 scrapers running simultaneously
    limiter: {
      max: 10,       // Max 10 jobs processed per 5 seconds globally
      duration: 5000,
    },
  },
);
```

### 6.2 Scheduling a Scraper

When a scraper is created or its schedule changes, a repeatable BullMQ job is created:

```typescript
// src/server/reports/scheduler.ts

export async function scheduleScraper(scraper: ScraperConfig): Promise<void> {
  // Remove existing repeatable job if present
  if (scraper.bullJobId) {
    await scraperQueue.removeRepeatableByKey(scraper.bullJobId);
  }

  if (!scraper.isActive) return;

  const job = await scraperQueue.add(
    `scraper:${scraper.id}`,
    {
      scraperId: scraper.id,
      userId: scraper.userId,
      template: scraper.template,
      config: scraper.config,
      isManual: false,
    },
    {
      repeat: { pattern: scraper.schedule, tz: 'UTC' },
    },
  );

  await db.scraperConfig.update({
    where: { id: scraper.id },
    data: {
      bullJobId: job.opts.repeat?.key,
      nextRunAt: new Date(await scraperQueue.getNextRunDate(scraper.id) ?? Date.now()),
    },
  });
}
```

### 6.3 Rate Limiting Per Domain

Before each Playwright request, the domain is checked against a per-domain rate limiter:

```typescript

  points: 5,          // Max 5 requests
  duration: 60,       // Per 60 seconds

export async function checkDomainRateLimit(url: string): Promise<void> {
  const domain = new URL(url).hostname;
  try {

    throw new Error(`Rate limit exceeded for domain: ${domain}. Retry in 60s.`);
  }
}
```

### 6.4 Retry Logic

BullMQ handles retries automatically with exponential backoff (see section 6.1). Additionally:
- After 3 failed attempts, the scraper's `ScraperConfig.isActive` is NOT automatically disabled (the user must manually diagnose and disable).
- A "consecutive failure" counter is tracked in the run history. If 5 consecutive runs fail, a push notification is sent to the user.
- Each failed run stores the full error message and any available screenshot in `ScraperRun.errorMessage` and `ScraperRun.screenshotUrls`.

### 11.1 Execution Architecture

Playwright scraper execution happens in a dedicated worker process, completely isolated from the main Next.js application:

```
│  Next.js App     │ ──────────────────► │  Scraper Worker Process        │
│  (web server)    │                     │                                │
└──────────────────┘                     │  ┌──────────────────────────┐  │
                                         │  │  Playwright Browser      │  │

                                         │  │                          │  │
                                         │  │  Sandbox restrictions:   │  │
                                         │  │  - No fs access          │  │

                                         │  └──────────────────────────┘  │
```

### 11.2 Sandboxing

```typescript
// src/server/reports/scraperSandbox.ts
import { chromium } from 'playwright';

const BLOCKED_INTERNAL_RANGES = [
  /^10\./,
  /^192\.168\./,
  /^172\.(1[6-9]|2\d|3[01])\./,
  /^127\./,
  /^localhost$/,
  /^::1$/,
];

export async function launchSandboxedBrowser() {
  const browser = await chromium.launch({
    headless: true,
    args: [
      '--no-sandbox',
      '--disable-setuid-sandbox',
      '--disable-dev-shm-usage',
      '--disable-gpu',
    ],
  });

  const context = await browser.newContext({
    // Intercept requests and block internal network access
    bypassCSP: false,
    javaScriptEnabled: true,
  });

  // Block requests to internal/private IP ranges
  await context.route('**/*', async (route) => {
    const url = new URL(route.request().url());
    if (BLOCKED_INTERNAL_RANGES.some((r) => r.test(url.hostname))) {
      await route.abort('accessdenied');
      return;
    }
    await route.continue();
  });

  return { browser, context };
}
```

```typescript
  fn: () => Promise<T>,
  timeoutMs: number = 30_000,
): Promise<T> {

    fn(),
```

### 12.3 Pre-Save Validation

Before a custom script is saved, it is statically analyzed for disallowed patterns:

```typescript
// src/server/reports/customScraperValidator.ts

const DISALLOWED_PATTERNS = [
  /require\s*\(/,                    // No require() calls
  /import\s+.*from/,                 // No ES imports (context is pre-injected)
  /process\./,                       // No process access
  /child_process/,                   // No subprocess spawning
  /fs\./,                            // No filesystem access
  /eval\s*\(/,                       // No eval
  /Function\s*\(/,                   // No dynamic function construction
  /fetch\s*\(/,                      // Use context helpers instead
  /XMLHttpRequest/,                  // No XHR
];

export function validateCustomScript(script: string): { valid: boolean; errors: string[] } {
  const errors: string[] = [];

  for (const pattern of DISALLOWED_PATTERNS) {
    if (pattern.test(script)) {
      errors.push(`Disallowed pattern detected: ${pattern.source}`);
    }
  }

  // Max script length
  if (script.length > 50_000) {
    errors.push('Script exceeds maximum length of 50,000 characters');
  }

  return { valid: errors.length === 0, errors };
}
```

### 12.4 Test Run

"Test Run" executes the script in the sandbox with a 30-second timeout and streams progress events back to the UI:

```typescript
// Progress events streamed during test run
export type TestRunEvent =
  | { type: 'navigating'; url: string }
  | { type: 'extracting'; selector: string }
  | { type: 'screenshot'; url: string }
  | { type: 'output'; data: unknown }
  | { type: 'error'; message: string; stack?: string }
  | { type: 'done'; durationMs: number };
```

The test run preview panel (below the editor) shows:
- A JSON tree viewer of the extracted output.
- Any console log output from the script.
- A "Screenshot" tab if `context.screenshot()` was called.
- Elapsed time.
